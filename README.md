# Homework4MuseumSystem

博物馆订票系统数据库课程设计项目。系统围绕游客预约、票务库存、在线支付、电子凭证、入园核销和后台运营管理展开。

```text

│   ├── E-R图.png                       # 实体-联系模型
│   ├── 大作业数据流图.png                # 游客端/管理端数据流
│   ├── 博物馆订票系统数据库结构设计.docx  # 数据库设计说明

├── 后端/                                # Spring Boot 后端服务
├── 游客端/                              # 游客端（待实现）
└── 管理端/                              # 管理端（待实现）
```

## 核心功能

- 游客注册、登录和实名参观人员管理
- 开放日期、参观场次、票种和库存管理
- 预约下单、支付、取消、过期和退款
- 电子入园凭证生成与二维码核销
- 后台订单、支付、核销、异常和统计管理
- 管理员、角色权限和操作日志

## 数据库

数据库使用 MySQL 8.0+，默认数据库名为 `museum_ticket`。执行脚本：

```sql
SOURCE /absolute/path/to/数据库层/museum_ticket_schema.sql;
```

脚本包含：

- 游客、实名人员、开放日期、场次、票种、库存、订单和订单明细表；
- 支付记录、电子凭证、核销记录、管理员、角色和操作日志表；
- 主键、外键、唯一约束和金额/库存检查约束；
- 带行锁、重复预约检查和异常回滚的 `create_ticket_order` 存储过程。

## 业务状态

- 订单：待支付、已支付、已取消、已退款、已过期
- 支付：未支付、已支付、已退款
- 凭证：有效、已使用、已作废、已过期
- 核验：未核验、已核验、已作废

## 当前状态

目前已完成游客侧核心后端闭环：注册登录、JWT、实名人员、票务查询、事务下单、订单查询、模拟支付、取消、自动过期、退款、电子凭证查询和入园核销。支付成功为每条订单明细生成唯一凭证；退款回退已售库存并作废凭证；核销使用独立密钥和凭证行锁防止重复入园。后端已使用 Java 25 和 Maven 编译并通过现有 7 项单元测试，关键事务 SQL 已在 MySQL 9.0 验证。游客端和管理端页面尚未实现。

### 已完成

- MySQL 中已创建 14 张业务表、14 条外键约束和 `create_ticket_order` 存储过程。
- 后端已连接 `museum_ticket` 数据库，`GET /api/system/health` 可检查服务与数据库状态。
- `POST /api/auth/register` 支持游客注册，不返回密码字段。
- `POST /api/auth/login` 支持密码校验、禁用状态检查、最后登录时间更新并签发 JWT。
- `GET /api/visitors/me` 使用 Bearer Token 查询当前登录游客。
- 密码使用 BCrypt 哈希存储，接口参数通过 Jakarta Validation 校验。
- JWT 使用 HMAC-SHA256 签名，支持签名校验、过期校验和受保护路由拦截。
- `GET/POST /api/real-persons` 支持查询和新增当前游客的实名人员。
- `PUT/DELETE /api/real-persons/{personId}` 支持修改和删除，并校验数据归属。
- 完整证件号码不落库；`id_hash` 保存带证件类型的 SHA-256 哈希，`id_masked` 保存脱敏值。
- `GET /api/ticketing/availability` 公开查询开放日期、场次、票种和实时可用库存。
- 可用库存按 `total_quantity - sold_quantity - locked_quantity` 计算，最低返回 0。
- `POST /api/orders` 支持一单多票的事务下单，订单默认 15 分钟内支付。
- `GET /api/orders` 和 `GET /api/orders/{orderId}` 仅查询当前游客的订单和明细。
- 下单按库存 ID 排序执行 `FOR UPDATE` 行锁，金额完全由服务端数据库票价计算。
- 已校验实名人员归属、票务状态、同日订单、库存数量及人员同场次重复预约。
- `POST /api/orders/{orderId}/pay` 支持微信、支付宝和其他渠道的模拟支付。
- 支付在同一事务中写入支付记录，并将锁定库存转为已售库存。
- `POST /api/orders/{orderId}/cancel` 允许游客取消待支付订单并释放库存。
- 定时任务每分钟关闭超过支付期限的待支付订单并释放库存。
- 支付和取消支持重复调用的幂等响应；订单和库存更新均带状态及数量校验。
- `POST /api/orders/{orderId}/refund` 支持未入园的已支付订单退款并回退已售库存。
- 支付成功后为每条订单明细生成 64 位随机哈希电子凭证。
- `GET /api/vouchers` 查询当前游客电子凭证、参观人和场次信息。
- `POST /api/verification/verify` 使用独立核销密钥验票，成功后更新凭证和明细并写入核销记录。
- 核销对凭证行执行 `FOR UPDATE`，重复、作废和过期凭证均不能再次入园。
- 单元测试已通过：共 7 项，覆盖 JWT、证件保护以及库存数量计算。

## 安全注意事项

- 生产环境只保存密码哈希，不保存明文密码。
- 证件号码应保存哈希或加密值，并在界面中脱敏显示。
- 支付回调必须验证签名并保证幂等。
- 游客只能访问属于自己的订单和实名信息。
- 数据库账号应使用最小权限，生产环境不要使用示例密码。
